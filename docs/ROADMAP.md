# Roadmapa: etapy 0–17

Bieżące zamknięcie MVP: Etap 3.5 zintegrowano do `main` przez fast-forward z `c4b0a6c` do `c57dbff`. Zrealizowano użytkowy zakres Etapów 13–14: podsumowanie ukończonej sesji i lokalny eksport Markdown / JSON / TXT. Raport korzysta z istniejącego replay i aktualnej projekcji adaptacji; nie obejmuje nieaktualnych decyzji. Nierozstrzygnięte pytania oraz częściowe źródło pozostają jawnie oznaczone. Pełny przepływ MD i TXT, wznowienie, korektę wcześniejszej odpowiedzi oraz rzeczywiste pobrania sprawdza runner Playwright w Edge/Chromium na szerokościach 1280 i 390 px. PDF / połączenie AI oraz fizyczny odbiór PWA pozostają poza tym zakresem.

Etapy są granicami zakresu i kryteriami odbioru. Etapy 0–3 są zakończone. Zrealizowany zakres Etapu 3 to wybór JSON, raport kontroli i jawne zatwierdzenie importu. Minimalny zapis zaakceptowanego quizu w IndexedDB i lista biblioteki zamykają ten przepływ. Etap 3.5 rozszerza wejście o tekst i Markdown przez niezależny parser oraz dotychczasowy walidator JSON 1.0.0. Historyczny checkpoint po Etapie 3 nie obejmował parsera ani runtime; późniejsze wykonane zakresy opisano poniżej. Istniejąca biblioteka definicji quizów stanowi fundament dalszych etapów, w tym Etapu 14; należy ją rozwijać, bez przepisywania od zera.

Etap 4 rozszerzono bieżącym poleceniem o podstawowy ekran pytania, uruchomienie z istniejącej Biblioteki, Dalej / Wstecz i lokalne ustawienie rekomendacji. Runtime wykonuje pojedynczy wybór w liniowej kolejności, waliduje odpowiedź względem pytania i utrzymuje roboczą historię zmienionych decyzji. Nieobsługiwane mechaniki, kompozycje, prezentacje wizualne, własna odpowiedź oraz reguły adaptacyjne otrzymują jawną odmowę wykonania. Standardowy wybór pozostaje dostępny obok informacji o niewykonywanym „Inne”.

Etap 5: trwałe, niezależne sesje tej samej definicji korzystają z domenowego modelu `Sesja` oraz istniejącej bazy `quizomat` po migracji 1 → 2. „Rozpocznij nową” zapisuje sesję przed wejściem; „Kontynuuj” wznawia konkretną sesję. Autosave obejmuje wybór i miejsce, Dalej / Wstecz oraz „Wróć później”. Lista odłożonych pozostaje widoczna przed zakończeniem i przetrwa restart. Błąd zapisu zachowuje poprzedni poprawny stan oraz umożliwia ponowienie. Migracja nie usuwa definicji quizów. Testy obejmują migrację, restart, wiele sesji i rzeczywisty abort transakcji.

Etap 6 według aktualnego polecenia: czysty replay i trwały, uporządkowany dziennik zmian decyzji, odłożenia i nawigacji. Stan bieżący jest odtwarzany z niezmiennej definicji, bazy oraz zdarzeń. Migracja 2 → 3 zachowuje dawne sesje i audyt, bez zgadywania brakujących operacji. Zapis nie pozwala skracać ani przepisywać dziennika. UI rozdziela historię od aktualnego wyboru. Testy obejmują A → B, A → B → A, kilka wcześniejszych pytań, restart, identyczny replay i brak nowych zdarzeń przy odczycie.

Zamknięcie etapów technicznych nie jest odbiorem gotowej aplikacji użytkowej. Etap 7 wykonuje istniejące reguły dodawania, pomijania i modyfikacji oraz odtwarza je przez replay Etapu 6. UI pokazuje każdą aktualną zmianę i „Dlaczego?”. Konflikty odrzuca dotychczasowy kontrakt 1.0.0; kolejność wykonania opisuje README silnika. Szersze mechaniki, zasoby, raport i eksport pozostają odłożone. Etap 8 wykonuje zapis szkicu, analizę i świadome zatwierdzenie własnej odpowiedzi przez istniejący dziennik; FakeAnalizator służy testom, bez integracji API. Numerację historycznej tabeli zachowano; aktualne polecenia definiują zakres Etapów 6–8. Wdrożenie prywatnego hostingu pozostaje osobną decyzją.
